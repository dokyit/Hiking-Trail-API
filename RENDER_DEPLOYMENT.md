## 🗄️ Step 2: Create PostgreSQL Database

1. Go to https://dashboard.render.com
2. Click **"New +"** → **"PostgreSQL"**
3. Configure:
   - **Name:** `hiking-trail-db`
   - **Database:** `hiking_db`
   - **User:** `hiking_user` (or leave auto-generated)
   - **Region:** Choose closest to you (Oregon recommended for US West, Ohio for US East)
   - **PostgreSQL Version:** 15 (or latest)
   - **Plan:** **Free**
4. Click **"Create Database"**
5. Wait for it to provision (takes ~1-2 minutes)

### Enable PostGIS Extension

6. Once the database is ready, click on it in your dashboard
7. Scroll down to **"Connections"** section
8. Click **"Connect"** → **"External Connection"**
9. Copy the **PSQL Command** (looks like `PGPASSWORD=xxx psql -h xxx...`)
10. Open your terminal and paste/run the command
11. Once connected to the database, run:
    ```sql
    CREATE EXTENSION IF NOT EXISTS postgis;
    \q
    ```

> **Alternative:** You can also use a GUI tool like pgAdmin or TablePlus with the connection string from Render.

## 🔴 Step 3: Create Redis Instance

1. Click **"New +"** → **"Redis"**
2. Configure:
   - **Name:** `hiking-trail-cache`
   - **Region:** **Same as your database** (important for low latency)
   - **Plan:** **Free**
   - **Maxmemory Policy:** `allkeys-lru` (automatically removes least recently used keys)
3. Click **"Create Redis"**
4. Wait for provisioning (~1 minute)

## 🐍 Step 4: Deploy Backend (Flask API)

1. Click **"New +"** → **"Web Service"**
2. Click **"Connect a repository"** and authorize GitHub
3. Select your `hiking-trail-api` repository
4. Configure:
   - **Name:** `hiking-trail-backend`
   - **Region:** **Same as database/Redis**
   - **Branch:** `main`
   - **Root Directory:** (leave empty)
   - **Runtime:** **Python 3**
   - **Build Command:** `./build.sh`
   - **Start Command:** `gunicorn -w 4 -b 0.0.0.0:$PORT run:app`
   - **Plan:** **Free**

### Add Environment Variables

5. Scroll down to **"Environment Variables"** and click **"Add Environment Variable"** for each:

| Key | Value | How to Get It |
|-----|-------|---------------|
| `DATABASE_URL` | (Use "Add from Database" button → Select `hiking-trail-db`) | Auto-filled |
| `REDIS_URL` | (Click "Add from Service" button → Select `hiking-trail-cache`) | Auto-filled |
| `GOOGLE_MAPS_KEY` | `AIzaSyBFkhKav7XM4-j2IsyMNNFCNrfXa4GUIOI` | Your actual Google Maps API key |
| `WEATHERSTACK_KEY` | `d7f9230e4f78afae248b5ca81a55c040` | Your actual WeatherStack API key |
| `SECRET_KEY` | (Click "Generate" button) | Auto-generated by Render |
| `JWT_SECRET_KEY` | (Click "Generate" button) | Auto-generated by Render |
| `FLASK_ENV` | `production` | Type manually |
| `PYTHON_VERSION` | `3.10.0` | Type manually |

6. Click **"Create Web Service"**

### Monitor the Build

7. Watch the build logs in real-time. You should see:
   - ✅ Installing Python dependencies...
   - ✅ Running database migrations...
   - ✅ Checking if trails need to be seeded...
   - ✅ Build complete!
   - ✅ Starting gunicorn...
   - ✅ **"Your service is live 🎉"**

8. **Important:** Copy your backend URL from the top of the page
   - It will look like: `https://hiking-trail-backend.onrender.com`
   - You'll need this for the frontend!

### Troubleshooting Backend Build

If the build fails:
- Check that `build.sh` has execute permissions (see Step 0.3)
- Verify all environment variables are set correctly
- Look for specific error messages in the logs
- Check that PostgreSQL has PostGIS extension enabled

## 🐛 Troubleshooting

### Issue: Backend build fails with "Permission denied: ./build.sh"

**Solution:**
```bash
chmod +x build.sh
git add build.sh
git commit -m "Make build.sh executable"
git push
```

### Issue: Database migration errors

**Solution 1:** Enable PostGIS extension
```bash
# Connect via PSQL (get command from Render dashboard)
CREATE EXTENSION IF NOT EXISTS postgis;
```

**Solution 2:** Manually run migrations
- Go to Render Dashboard → Your Backend Service
- Click "Shell" tab
- Run: `flask db upgrade`

### Issue: "No trails found" after successful build

**Solution:** Manually seed the database
- Go to Render Dashboard → Your Backend Service → Shell
- Run: `python seed_mass_trails.py`
- Wait for completion (~30 seconds)

### Issue: Map doesn't load on frontend

**Check 1:** Verify Google Maps API key
- Make sure `REACT_APP_GOOGLE_MAPS_KEY` is set in frontend environment variables
- Verify billing is enabled on Google Cloud Console
- Check that Maps JavaScript API is enabled

**Check 2:** Check browser console for errors
- Press F12 → Console tab
- Look for API key errors or CORS issues

### Issue: Weather not showing

**Solution:** Check WeatherStack API
- Verify `WEATHERSTACK_KEY` is correct in backend environment variables
- Check free tier limits (1,000 requests/month)
- Test manually: `curl "http://api.weatherstack.com/current?access_key=YOUR_KEY&query=Boston"`

### Issue: Frontend shows "Network Error" or can't connect to backend

**Solution 1:** Verify REACT_APP_API_URL
- Check that it's set to your backend URL (e.g., `https://hiking-trail-backend.onrender.com`)
- Make sure there's NO trailing slash
- Rebuild frontend after fixing

**Solution 2:** Add CORS to backend
If you get CORS errors, update `app/__init__.py`:

```python
from flask_cors import CORS

def create_app(config_class=Config):
    app = Flask(__name__)
    app.config.from_object(config_class)
    
    # Add CORS support
    CORS(app, resources={
        r"/api/*": {
            "origins": ["https://hiking-trail-frontend.onrender.com"],
            "methods": ["GET", "POST", "PUT", "DELETE"],
            "allow_headers": ["Content-Type", "Authorization"]
        }
    })
    
    # ... rest of your code
```

Add to `requirements.txt`:
```
flask-cors==4.0.0
```

Commit and push to trigger rebuild.

### Issue: Free tier service "spins down" after 15 minutes

**This is normal!** Free tier web services on Render automatically sleep after 15 minutes of inactivity.

**Solutions:**
1. **Accept the 30-second cold start** - First request after sleep takes ~30s
2. **Use UptimeRobot** (free) - Pings your app every 5 minutes to keep it awake
   - Sign up at https://uptimerobot.com
   - Add your backend URL as a monitor
   - Set interval to 5 minutes
3. **Upgrade to paid plan** - $7/month keeps services always running

## 💰 Free Tier Limits

### Render Free Tier Includes:

| Resource | Limit | Notes |
|----------|-------|-------|
| **Web Services** | 750 hours/month | Enough for 1 service running 24/7 |
| **Static Sites** | Unlimited | Unlimited bandwidth! |
| **PostgreSQL** | 1 GB storage | Expires after 90 days (just recreate) |
| **Redis** | 25 MB storage | Enough for caching |
| **Build Minutes** | Unlimited | No limit on deploys |

### Important Free Tier Notes:

- ⏱️ Free web services **spin down after 15 minutes of inactivity**
- 🐌 First request after spindown takes **~30 seconds** (cold start)
- 🗄️ PostgreSQL free databases **expire after 90 days** - you'll need to create a new one and reseed
- 🔄 Static sites have **no spin down** - always instant!

### Keep Your App "Warm":

Use [UptimeRobot](https://uptimerobot.com) (also free) to ping your backend every 5 minutes:
1. Sign up at uptimerobot.com
2. Add Monitor → HTTP(s)
3. URL: `https://hiking-trail-backend.onrender.com/api/trails/search?city=Boston`
4. Monitoring Interval: 5 minutes
5. Save!

## 🔐 Security Best Practices

### ✅ Already Implemented:

- API keys stored as environment variables
- `.env` file in `.gitignore`
- No hardcoded secrets in code
- HTTPS by default on Render
- JWT authentication for protected routes

### 🔒 Extra Security (Optional):

1. **Rate Limiting** - Add to backend:
```python
from flask_limiter import Limiter
from flask_limiter.util import get_remote_address

limiter = Limiter(
    app,
    key_func=get_remote_address,
    default_limits=["200 per day", "50 per hour"]
)

@app.route("/api/trails/search")
@limiter.limit("10 per minute")
def search_trails():
    # Your code here
```

2. **API Key Rotation:**
   - Rotate your Google Maps and WeatherStack API keys every 90 days
   - Update them in Render environment variables
   - Redeploy services

3. **Monitoring:**
   - Set up Render notifications for build failures
   - Use Render metrics to track usage
   - Set up alerts for unusual traffic

4. **Backup Database:**
   - Render doesn't auto-backup free databases
   - Manually backup before the 90-day expiration:
   ```bash
   # Get connection string from Render dashboard
   pg_dump "your_connection_string" > backup.sql
   ```
